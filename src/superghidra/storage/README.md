## 2. Key Data Structures, Scope Caveats & Invariants
- **Synthetic Benchmark & `.sgdb` Container Scope:**
  - Upstream Ghidra hardcodes `LocalManagedBufferFile` inside its private `LocalFileSystem` storage path and does not expose a plugin SPI to swap out `.rep` B-tree buffer files at runtime.
  - Because of that upstream restriction, `CompressedLocalManagedBufferFile` and `SuperGhidraCodec.jar` read and write standalone `.sgdb` sidecar containers rather than drop-in `.rep` databases, and the 16 KB page compression figures (~79% LZ4 / ~86% Zstd reduction) are measured on synthetic pages generated by `GhidraPageSimulator`, not live `.rep` project directories.
- **`SlotDirectoryEntry` Layout (20 Bytes):** Packed `<IQII` (`block_id: uint32`, `offset: uint64`, `compressed_len: uint32`, `original_len: uint32`).
- **Java `.sgdb` Interop Container (`SGDB` Magic):**
  - Append-only frame writes with crash-safe two-phase `sync()` (slot directory + parameters + free-list written first, `fsync()`, then header directory pointer updated, `fsync()`).
  - Frame compression flag always records the actual codec stored (`NONE=0`, `LZ4=1`, `ZSTD=2`), falling back to uncompressed when random data is incompressible.
- **Extension Structure Invariant:** `SuperGhidraCodec-1.0.0.zip` must root all entries under `SuperGhidraCodec/` with `extension.properties`, `Module.manifest`, and `lib/SuperGhidraCodec.jar`.
